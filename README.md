# 分时试价交接

试价只涉及一种商品，原分配、曝光和支付是现场各自上报的源账。馆店共用小程序价格时以渠道组为准。 数据全部为合成业务记录。文件使用 UTF-8 JSON，时间均为北京时间，货币如无单独说明均为人民币分。

## 查阅交接数据

使用 Python 3.11 标准库。在仓库根目录运行 `python3 inspect_delivery.py` 查看交接文件和行数，或在后面加文件名（含 `.json`）查看该文件的第一条记录。这个入口仅供查阅交接资料。

## 数据约定

- `plan.json` 配对时段、馆店、起止时间和原分配。对照关系来自 pair，不从成交价还原。
- `exposure.json` 每时段门口客流；actual 为现场观测，cross_exposure 记录有串价，register_down 表示该时段收银离线无法补齐。该字段为发布政策定义的整对排除条件。
- `orders.json` 订单按时间送达，支付额和可变成本为单笔商品口径。
- `refunds.json` 退款追溯原订单，退货均重新可售，退款时返还该笔可变成本。
- `rules.json` 各次证据复盘日、退货观察窗、时段首尾过渡分钟数、最少完整对数及所用区间下界门槛。每个馆先形成自身估计，整体口径各馆等权；区间置信度见 confidence。
- `channel_terms.json` 馆店、渠道、共享价组和最低毛利率。较晚的 known 对后续候选生效；核价口径为（售价减可变成本）除以售价。
- `offers.json` 已承诺报价。有效报价低于拟切换的保护底线时仍按承诺执行；共用价渠道如还有旧报价待执行，则整组延后切换。
- `costs.json` 可变成本生效日和已知时间。

## 检查资料

运行 `python3 -m unittest discover -s tests -v`。检查会读取当前交接文件，核对该业务所需的关键原始证据是否齐备。
